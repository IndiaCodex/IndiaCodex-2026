Adaptive Concurrency-Aware Batcher

The shared, adaptive batching layer every Cardano dApp needs — but currently rebuilds from scratch. It detects which pending requests collide over the same UTXO, reads live network congestion, and settles the largest non-conflicting set in one transaction.

Infrastructure, not an app · demonstrated end-to-end on Preprod-ready code

01 · The problem

On Cardano, a UTXO can be spent by one transaction at a time.

Under the eUTXO model, when many users hit the same contract at once, their transactions collide over the same UTXO. Only one wins — the rest fail on-chain, and can still pay fees.

50 claimers
all target the same ticket UTXO
→
1 UTXO
spendable once per block
→
49 fail
contention, wasted fees

The single most-cited technical limitation of building on Cardano.

02 · Today

Everyone rebuilds the same batcher. Nobody shares it.

Minswap, SundaeSwap and others each built their own bespoke, static, rule-based off-chain batcher to work around contention. There is no shared, adaptive infrastructure layer — every serious protocol reinvents it.

  • Reinvented per team — wasted effort, inconsistent reliability.
  • Static — fixed rules that don't react to live network conditions: batch too conservatively when quiet (wasted throughput) or poorly when congested (failed / overpriced txs).
  • The gap — reusable, adaptive infrastructure any dApp can plug into.
03 · The solution

Detect conflicts · read congestion · settle the largest safe set in one tx.

Conflict Detector
builds a contention graph of pending requests
→
Congestion Predictor
live score 0–1 (EWMA of block fullness)
→
Batch Optimizer
max independent set + adaptive timing
→
Aiken validator
settles the batch, state stays split

Adaptive is the new part: the congestion score reshapes batch size and timing live — quiet → clear fast for low latency; congested → wait, batch bigger, submit fewer larger transactions.

06 · Positioning

Infrastructure — like ERC-4337 bundlers, but structurally necessary here.

What it is

The same category as Ethereum bundlers or CoW Protocol's solvers — applied to a chain where, because of eUTXO contention, adaptive batching isn't an optimization, it's a requirement for high-concurrency dApps.

What it is not

Not an AI breakthrough. Conflict detection is graph theory; congestion is an EWMA. We deliberately didn't fake a model. The value is reusable infra + adaptive policy — and we say so.

  • Moat — trusted shared infrastructure + a network-effect flywheel: more dApps routing through it → better view of real contention → better batching → more attractive to the next dApp.
07 · Risks, named openly

Every weakness, with an answer.

  • Small TAM (~$130M Cardano DeFi TVL) — infra bets on ecosystem growth; it reduces a top friction to that growth, and fits Catalyst funding for exactly this.
  • Leios (base-layer scaling) — raises throughput but doesn't make application-level contention resolution free. Complementary, not obsoleted.
  • Centralization / front-running — next step: staked, slashable batcher operators or a competitive solver auction, so the role is punishable and contestable.
  • On-chain cost is ~O(n³) — the validator runs once per input, each doing list.find/count per claim (measured: N_max ≈ 6–7). Fix: Dict O(1) lookups → ~O(n²) total, far higher N_max. A concrete optimization we found by hitting the limit on-chain.
08 · The ask

Infrastructure the whole Cardano DeFi ecosystem needs.

This is a proof of concept — a working off-chain agent, an on-chain Aiken settlement validator with a measured execution budget, and a live demo with a verifiable fees-saved number.

The natural next step is a Project Catalyst proposal: staked-operator network, real-mempool conflict detection (via Maestro), and multi-dApp routing.
