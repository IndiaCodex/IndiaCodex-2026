# Sentinel v0.1.0 — "Hackathon MVP"

**Release date:** 2026-07-15
**Tag:** `v0.1.0` (first public release)

Sentinel's first release: a complete, working Engineering Assurance pipeline for
autonomous agents — capture, journal, replay, verification, explainability, and
export — with a live Masumi payment-enrichment integration and a full web
console over all of it. Everything in this release runs from a single command
on a machine that has never seen the repository before.

## Highlights

- **A real, live Masumi integration**, not a mock bolted on for a demo.
  `CaptureEventUseCase` routes every payment event through
  `MasumiAdapterPort.enrichPayment()` during capture — visible in both the
  seed script's terminal output and the Explainability tab's Payment Flow
  table. See [ADR-0009](../adr/0009-live-masumi-enrichment-at-capture.md).
- **A deterministic, non-AI assurance pipeline.** No code path in Execution
  Capture, the Execution Journal, Replay, Verification, or Explainability
  calls an LLM or any nondeterministic service — enforced structurally by
  `appendJournalEntry`'s Snapshot invariant, not by convention alone.
- **A complete Engineering Console.** Dashboard (with a real execution-status
  distribution chart), Executions list with search/filter, and five
  per-execution tabs: Timeline, Replay, Verification, Explainability, and
  Artifact export.
- **One command to see all of it**: `pnpm demo` builds every package, seeds
  four realistic scenarios (success, tool failure, declined Masumi payment,
  interrupted execution), and starts both services.
- **171 tests across 28 files**, stable across repeated runs, including a
  shared `StoragePort` contract suite proving the SQLite and in-memory
  adapters are genuinely interchangeable, not just structurally similar.
- **Full documentation set**: architecture guide, HTTP API reference, 9
  Architecture Decision Records, development guide, and an honest,
  specific "known limitations" list.

## Features

| Area                       | What's included                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Execution Capture          | Typed HTTP API (`POST /events`) validating lifecycle, tool, decision, and payment events against zod schemas and domain invariants                                       |
| Execution Journal          | Append-only, hash-chained record (SHA-256 over canonical JSON); tamper-evident by construction                                                                           |
| Masumi Integration         | Live `MasumiAdapterPort.enrichPayment()` call during payment capture, with graceful degradation if Masumi is unreachable                                                 |
| Replay Engine              | Deterministic reconstruction from recorded Snapshots after independent re-verification; never re-invokes a live LLM, tool, API, or Masumi service                        |
| Verification Engine        | Six independent checks (schema version, event ordering, identity consistency, snapshot consistency, hash chain, root hash), recomputable from an exported artifact alone |
| Engineering Explainability | Deterministic, rule-based execution summaries, timeline narratives, tool flow, payment flow (with Masumi references), and failure analysis                               |
| Audit Export               | One portable, self-contained JSON file — artifact, hash chain, verification report, replay session, explainability — sufficient on its own to audit an execution         |
| Web Console                | Dashboard, Executions list, and five per-execution tabs; dark by default, light theme available; zero console errors across every page in verification                   |
| Storage                    | SQLite (default) and in-memory adapters behind one `StoragePort`, validated by a shared contract test suite                                                              |

## Known limitations

Stated here deliberately, not discovered later — the same list lives in
[`docs/roadmap.md`](../roadmap.md) and [`SECURITY.md`](../../SECURITY.md):

- No authentication or authorization on the HTTP API.
- No rate limiting; CORS defaults to allow any origin (narrow with
  `SENTINEL_CORS_ORIGIN` before exposing beyond localhost).
- No concurrency control on Journal writes — two concurrent `append()` calls
  for the same execution aren't locked.
- No migration framework — SQLite schema is `CREATE TABLE IF NOT EXISTS`
  only, acceptable for one schema version.
- No PII/secret redaction — Snapshots store LLM/tool/API payloads verbatim.
- No artifact signing — tamper-evidence is the hash chain alone;
  `ExecutionArtifact.signature` is always `null`.
- Client-side search/filter/sort only (correct at demo scale, not at
  production scale — see [ADR-0008](../adr/0008-client-side-search-and-filtering.md)).
- No cross-package TypeScript project references — `build` must precede
  `lint`/`typecheck`/`test`.
- Assistant Mode (LLM-based) explainability doesn't exist — Engineering Mode
  only, by design (see [ADR-0002](../adr/0002-dual-mode-explainability.md)).
- No OpenAPI spec — `docs/api.md` is hand-maintained.
- `MasumiAdapterPort` is backed by `MockMasumiAdapter`; a real Masumi client
  is a drop-in replacement behind the same port, not yet written.

None of these are hidden defects — they're explicit scope boundaries for a
v0.1.0 built to demonstrate a complete, correct pipeline first.

## Future roadmap

Roughly in priority order (full detail in [`docs/roadmap.md`](../roadmap.md)):

1. A real Masumi client behind `MasumiAdapterPort`, replacing the mock.
2. Artifact signing (Ed25519 or similar) for genuine third-party auditability.
3. A PostgreSQL `StoragePort` adapter, validated against the existing
   contract suite.
4. Redaction/scrubbing policy for Snapshot payloads before export or sharing.
5. AuthN/AuthZ and multi-tenancy.
6. A server-side, indexed search index once client-side filtering stops
   being sufficient.
7. TypeScript project references across the workspace.

## Installation

Requirements: Node.js ≥ 22, pnpm ≥ 11.

```bash
git clone <this-repo>
cd Sentinel
pnpm install
pnpm demo
```

Open `http://localhost:5173`. See [`README.md`](../../README.md#quick-start)
for the manual, step-by-step alternative and
[`docs/development.md`](../development.md) for the day-to-day dev loop.
