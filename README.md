# IndiaCodex'26

**Cardano hackathon · 11–12 July 2026 · Hyderabad, India**
Powered by [Nucast Labs](https://nucast.io/) · [indiacodex.com](https://www.indiacodex.com/)

IndiaCodex'26 was the fourth edition of the IndiaCodex developer hackathon series, run to onboard Indian developers to Cardano. This repository is the permanent archive of every project submitted to the event.

---

## Event summary

### Participation

IndiaCodex'26 ran as a two-day in-person event in Hyderabad, preceded by three virtual workshops and followed by a ten-day nationwide build phase.

| | Day 1 — Inaugural | Day 2 — Workshop & Hackathon |
|---|---|---|
| **Date** | Saturday, 11 July 2026 | Sunday, 12 July 2026 |
| **Venue** | EThames Business School, Raidurg | DraperU India, Gachibowli |
| **Hours** | 5:00 PM – 8:00 PM | 9:00 AM – 9:00 PM |
| **Registered** | 476 | 515 |
| **Attended / checked in** | 167 | 271 |

Day 2 drew the higher turnout as the main build day, consistent with previous IndiaCodex editions. The hacking arena was arranged across two floors with mentors stationed on both.

Registration figures are Luma RSVP counts; attendance figures are door check-ins recorded through Luma's check-in system.

## Results

**42 teams submitted 47 projects** across three tracks. Several teams entered more than one track with distinct projects. Every submission is listed in **[SUBMISSIONS.md](SUBMISSIONS.md)** with its track, participant and code location.

Judging was conducted in two rounds, scored on technical execution, originality, Cardano integration and presentation.

### General Track & Community Choice

Judged on-site; winners announced at the awards ceremony on 12 July 2026.

| Place | Project | Description |
|---|---|---|
| 🥇 1st | **Ouro** | A self-repaying lending protocol on Cardano. Collateral keeps earning staking rewards, harvested every epoch to automatically pay down the loan. |
| 🥈 2nd | **Proof Pair** | A decentralised HTTP 402 payment gateway letting APIs charge per-request micro-payments in ADA, with no accounts or subscriptions. |
| 🥉 3rd | **Foundry** | An AI agent workforce turning a plain-language product idea into deployable Cardano artifacts: Aiken contracts, frontend scaffolds, audits and docs. |
| 🏅 Community Choice | **Forge** | An intelligent Cardano development platform turning a described intent into a compiled Aiken project, CIP-57 blueprint and typed TypeScript SDK. |

### Masumi Track

Judged by the Masumi team following the ten-day build phase; winners announced 23 July 2026.

| Place | Project | Description |
|---|---|---|
| 🥇 1st | **ANTIDOTE** | An immune system for AI agent fleets that detects, quarantines and purges corrupted data using on-chain Aiken contracts and an incentivised doubt-market. |
| 🥈 2nd | **Sentinel** | A deterministic trust and audit platform for autonomous AI agents, producing replayable execution journals and tamper-evident cryptographic evidence. |
| 🥉 3rd | **ArgoOperator** | A web-to-Cardano agent gateway giving AI agents a real browser, paid through Masumi ADA escrows released only on verifiable proof-of-execution. |

### Midnight Track

Judged by the Midnight team following the ten-day build phase; winners announced 23 July 2026.

| Place | Project | Description |
|---|---|---|
| 🥇 1st | **Compass** | A deterministic compatibility and ecosystem analysis platform for Midnight, validating dependencies, mapping risks and generating evidence-based upgrade reports. |
| 🥈 2nd | **Confidential Proof of Reserves** | A Midnight dApp proving a custodian's liabilities stay within its public reserves using zero-knowledge proofs, without revealing any customer balance. |
| 🥉 3rd | **MedVault** | A privacy-preserving health insurance platform on Midnight and Cardano where claims settle through zero-knowledge proofs instead of exposed medical records. |

## Repository structure

Each submitted project lives in its own top-level folder, named after the submitting team or project.

```
IndiaCodex-2026/
├── README.md          ← this file
├── SUBMISSIONS.md     ← full index of all 47 projects
├── CONTRIBUTING.md    ← the original submission process
├── <TeamName>/        ← one folder per submitted project
└── ...
```

Participants submitted by opening an issue and a pull request from a fork. All 29 pull requests have been processed and all 50 submission issues triaged and closed; three issues were duplicate filings, giving 47 distinct projects.

A small number of pull requests conflicted on the root `README.md` because participants edited it alongside their own folder. Where GitHub could not auto-resolve the conflict, those project files were committed to `main` directly with the original author credited in the commit message and a note on the pull request. Projects whose authors hosted their code in their own repository rather than opening a pull request are linked from `SUBMISSIONS.md`.
